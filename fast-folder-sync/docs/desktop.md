# Fast Folder Sync 桌面版

## 开始使用

客户端采用浅色毛玻璃风格，提供半透明导航、任务概览卡片、磨砂任务卡片和弹窗。Windows 使用原生系统窗口按钮，顶部标题栏可拖动、双击最大化；支持系统原生亚克力材质的 Windows 会同时显示窗口背景模糊。界面也提供渐变底色，并响应减少动态效果、减少透明度和高对比度偏好。

Windows 用户可运行提供的便携版 `Fast-Folder-Sync-0.3.0-Windows-x64.exe`。首次打开没有预设任务，也不会扫描其他文件夹。

1. 点击「新建任务」，填写名称并选择源文件夹。
2. 选择目标类型，再选择目标文件夹或填写私有服务配置。
3. 选择单向备份或双向同步，设置核对间隔和排除规则。
4. 保存后点击「立即同步」。开启自动同步的任务会定期核对；程序重新打开时也会恢复自动任务。
5. 关闭窗口会隐藏到托盘，继续运行。完全退出请使用托盘菜单「退出」。

可以双击任务卡片中的本地路径打开文件夹。每个任务的目录需要独立，不允许与其他任务的目录重叠；源与目标也不能相同或嵌套。目标目录应先存在，可以在系统目录选择窗口中创建。

## 目标和模式

| 目标 | 单向备份 | 双向同步 |
| --- | --- | --- |
| 本地目录、移动磁盘、已挂载 SMB/NAS 目录 | 支持 | 支持 |
| 配套 Folder Sync 私有服务 | 当前不提供 | 支持，已完成本地真实服务联调 |

单向备份把源文件复制到目标；目标中的独有文件默认保留。源与目标同名但内容不同时，以源为准，先将旧目标内容保存为历史版本。

双向同步会比较本次两端内容和上次成功的基线：只改一端则复制到另一端，两端同时改动则保留目标的 `.conflict-<内容摘要>` 副本，再同步源版本。下一轮把冲突副本同步到两端。不会尝试自动合并二进制文件。

删除传播默认关闭。开启后，只传播有成功基线且另一端未发生新修改的删除；「一端删除、另一端编辑」保留编辑后的内容。删除前会备份文件。空目录会复制，目录本身不会被递归删除；文件重命名通常表现为新增路径和旧路径的删除或保留。

源或目标消失、读写失败、文件在传输中变化、状态损坏时，该轮报错，不提交新的成功基线。已完成的单个文件操作不会整体回滚，后续会重新核对。复制使用相邻临时文件，校验成功后再替换正式文件。

## 私有服务

填写服务根地址（例如 `https://sync.example.com`，反向代理前缀也支持）、服务端仓库名、有效令牌。令牌通过操作系统的 Electron `safeStorage` 加密保存；操作系统加密不可用时不保存令牌。同步与本地历史文件本身没有额外加密。

建议为通用文件夹建立独立仓库，不要直接绑定现有生产 Obsidian 库。适配器复用现有 JSON WebSocket 协议，包括鉴权、元数据分批、首个下载页请求、分页确认、文件分块、上传确认和断线重试核对。当前不启用 Protobuf，也不需要 Obsidian API。

配套 0.3.0 服务端通过 `/api/drive/capabilities` 声明通用文件能力。客户端会将所有新文件统一通过二进制协议传输，包括 Markdown；文件摘要使用完整 SHA-256。已有旧文本资源继续按原资源类型同步。客户端会记住已识别的能力，临时网络错误不会让资源类型改变。

连接未改造的原服务端时保留兼容模式：UTF-8 且不超过 8 MiB 的 `.md` 走旧文本协议，其他文件走二进制协议；已有 Markdown 改变编码或跨越该阈值时拒绝切换类型。原服务端的大文件摘要使用头部、中间、尾部采样；若完整 SHA-256 已变而采样摘要不变，客户端会停止并报错。配套改造服务端使用完整摘要，没有这一采样限制。

路径仍沿用兼容的 32 位摘要；客户端及改造服务端会拒绝检测到的路径冲突，避免覆盖其他文件。

本轮已上传确认的内容才会记入基线。服务端拒绝的操作和鉴权错误会显示在任务中。已在本机真实 Go 服务完成两台客户端双向同步、空文件、非 UTF-8 文件和 26 MiB 大文件修改验证；用户的远程部署仍需按其地址、代理和权限配置验证。

## 历史恢复

覆盖、删除和恢复前的旧文件保存在应用数据目录的 `history/<任务 ID>/` 中，每个版本有独立的原始文件和 JSON 元数据。它们位于同步目录之外，不会被传到目标。

恢复步骤：先关闭该任务的自动同步，进入「历史版本」，选中任务和版本，再点击恢复。恢复到记录中的原路径及原侧（源或目标）；覆盖现有文件之前仍会保存新历史。确认恢复内容后再启用自动同步，后续传播遵循任务模式。

历史版本没有自动清理上限，请自行管理磁盘空间。应用内「打开应用数据目录」可找到配置、同步状态和历史文件。移除任务只删除配置，保留文件及历史备份；移除后该任务的历史不再显示在界面中，原始备份仍可从数据目录取回。

## 排除规则

每行一条，支持 `*.tmp`、`cache/**`、`build/output/**` 等 glob 规则。没有斜杠的规则匹配各层的名称，有斜杠的规则按相对路径匹配。当前不支持 `!` 反向规则。

默认排除 `.git`、`node_modules`、`.DS_Store`、`Thumbs.db`、`.fast-folder-sync`、`*.ffs-tmp`，并跳过符号链接／Windows junction。其他隐藏文件会同步。Windows 保留名称及不兼容路径会报错，不会悄悄跳过。

调整路径、目标类型、模式或删除策略时需要新建任务，避免复用错误基线；名称、间隔、排除规则和令牌可以编辑。正在运行的任务需要先暂停。

## 开发与构建

```powershell
cd desktop
npm ci
npm run check
npm test
npm start
npm run dist:win
```

其他系统可使用 `npm run dist:mac`、`npm run dist:linux`。跨系统原生包应在对应系统构建和验证。上游插件仍使用原来的根目录构建命令。

| 文件 | 职责 |
| --- | --- |
| `desktop/main.cjs` | 窗口、托盘、配置、加密令牌、任务调度、受限 IPC、历史恢复 |
| `desktop/preload.cjs` | 主进程与隔离渲染界面的接口 |
| `desktop/lib/files.cjs` | 路径边界、全量摘要、扫描、历史归档、临时写入 |
| `desktop/lib/local-sync.cjs` | 本地备份和三方基线双向同步 |
| `desktop/lib/fns-sync.cjs` | 独立的 Fast Note Sync 协议客户端 |
| `desktop/renderer.js` / `index.html` / `style.css` | 中文任务、活动和历史界面 |

当前版本采用定期扫描，间隔 10～86400 秒，默认 30 秒；每轮会读取完整文件计算 SHA-256。大目录的扫描成本与文件总量有关。它同步文件内容及修改时间，不保留 ACL、扩展属性、稀疏布局、硬链接关系或完整文件系统快照。任务之间目录独立，同一任务串行执行。

活动日志只在本次运行期间保留最近 500 条，历史版本持久保存。当前没有系统开机自启设置、后台系统服务、端到端加密、S3/WebDAV/Git 直接适配，也没有在线发布／自动升级。Windows 构建未进行代码签名。
