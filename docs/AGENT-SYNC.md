# Agent Sync 使用与验证

Agent Sync 是 Fast Folder Sync 在原有版本基础上新增的「Agent 记忆同步」功能，面向个人用户在多台电脑、Codex / Claude Code / ZCode / WorkBuddy 之间延续已有记忆与规则。桌面端继续默认打开原文件夹任务首页；原有文件同步、备份、同步记录和历史版本入口保持不变，已有任务保留原配置。通过侧栏「Agent 记忆同步」进入新增工作台，并可随时返回原功能。

## 开始使用

1. 运行 `npm run desktop:start`，在原首页侧栏点击「Agent 记忆同步」。
2. 在「项目与 Agent」创建共享项目，选择本机项目目录及使用的 Agent。各电脑应关联同一个共享项目，而非分别创建同名项目。
3. 在「记忆来源」点击「识别本机 Agent」，预览并勾选来源，为其指定所属项目。只有跨项目通用内容才选择「个人通用」。Codex 的原生记忆可能含多个项目资料，须自行确认后选择所属项目，不能直接作为个人通用记忆导入。
4. 点击「保存选择并采集」，再点击「整理并同步」。项目的 `AGENTS.md`（Codex、ZCode）、`CLAUDE.md`（Claude Code）或 `CODEBUDDY.md`（WorkBuddy）会获得带标记的读取入口。
5. 在「设备同步」连接专用私有服务文件库或已挂载的共享目录；其他电脑使用相同目标。私有服务沿用原有部署和设备令牌，跨电脑连接要求 HTTPS。
6. 第二台电脑先同步，选择下载的已有项目，关联它在该电脑上的目录，再选取本机记忆来源。

「已提供给 Agent」表示对应项目生成了可读取的文件和指令入口，并不表示工具已经读取或验证了内容。建议在目标 Agent 的新会话中询问一条明确的项目约定，并检查使用情况。部分工具的沙箱或指令设置可能要求额外允许读取项目内的文件。

### 自动整理

在「自动整理」填写 OpenAI 兼容服务的 API 基础地址（例如以 `/v1` 结尾）、模型名称和 API Key。配置后经验记忆原文会发往此服务，可能产生模型费用。本机模型可使用 `http://127.0.0.1:端口/v1`，远程服务要求 HTTPS。保存后点击「整理并同步」。

语义整理策略默认开启，未配置模型时只做无损同步。每轮最多处理 5 条待整理记忆；失败后对该版本间隔一小时重试，不阻断同步。超过 60000 字符的单条记忆继续使用原文。规则不送往模型压缩；摘要额外保留含“禁止、不要、必须、never、must”等约束的原句。摘要不保证语义完全等价，原文始终可追溯。

自动处理默认每 30 秒执行一次，可以在页头关闭。关闭自动处理后仍可手动整理并同步。

## 记忆与恢复

- 共享记忆库：应用数据目录内的 `agent-sync/shared/`，每个追加版本为内容寻址的 `.json.gz` 文件。压缩用于无损传输；共享库包含原文，不是端到端加密存储。
- 记忆分为个人通用和项目记忆。项目记忆只输出到对应项目；个人记忆输出到已关联的项目。未关联项目不会安装读取入口。
- 项目输出为 `.agent-sync/INDEX.md`、`CATALOG.md`、`RULES.md`、`topics/` 和 `sources/`。短索引最多展示 60 条，完整目录按需搜索，区分个人/项目和规则/经验。摘要与原文分开，规则保持原文。已知的来源项目根路径在输出中映射为本机根路径，其他机器专属路径仍需使用者核对。
- 「查看与编辑」保存新版本；「停用」或「删除」会移除对应生成文件。删除记录继续同步，原生记忆不改写。若要恢复，在「显示已删除」中打开历史并恢复版本。
- 原生来源内容未变时不会再次导入；原生来源消失或取消勾选不会自动删除已导入记忆，请在工作台明确删除。
- 两台电脑同时修改会保留分支并暂停提供该条记忆。查看历史、选择一个版本恢复，或编辑合并内容，即可生成包含所有当前分支的新版本。相同内容的重复导入不会被误报为冲突。
- 可检测措辞直接相反的规则（例如“禁止自动提交”与“必须自动提交”），暂停提供并提示处理；不能识别所有自然语言矛盾，需结合原文审阅。
- 「撤销读取入口」只移除产品自己的标记区域和带产品标记的生成文件，保留原有规则。覆盖前文件副本保存在 `agent-sync/output-history/`。原来不存在的指令文件撤销后可能留下空文件。

选择来源时跳过常见疑似凭据；不会扫描登录配置、聊天记录或 Skills。检测不是完整的秘密识别系统，分享前仍应预览。模型密钥和设备令牌通过 Electron safeStorage 使用系统加密，只保存在本机 `local.json`，不进入共享库。系统加密不可用时拒绝保存凭据。

试用反馈按钮记录“正确使用、还需重复交代、记错、过期”，仅写入本机 `agent-sync/feedback/`，不后台上报。

## 架构与兼容

不迁移旧任务，不修改现有服务端同步协议。桌面客户端继续使用原应用标识与用户数据目录，避免升级后丢失已有配置。产品发布版本仍由根目录 `VERSION` 统一管理，0.3.0 随配套客户端与服务端统一发布。

适配器只读取选定的 Markdown 记忆与规则，不覆盖工具内部数据库。当前识别默认主目录下的：

| 工具 | 来源 |
| --- | --- |
| Codex | `.codex/memories/`、`.codex/AGENTS.md`、已关联项目的 `AGENTS.md` |
| Claude Code | `.claude/projects/*/memory/`、`.claude/CLAUDE.md`、`.claude/rules/`、项目 `CLAUDE.md` 和 `.claude/rules/` |
| ZCode | `.zcode/cli/memories/projects/*/memory/`、`.zcode/AGENTS.md`、项目 `AGENTS.md` |

WorkBuddy 识别 `~/.workbuddy/MEMORY.md`、`~/.workbuddy/user-*/MEMORY.md`、`~/.workbuddy/rules/` 中的 Markdown/MDC，以及已关联项目的 `.workbuddy/memory/`、`.workbuddy/rules/` 和 `CODEBUDDY.md`（不存在时读取 `AGENTS.md`）。只采集实际存在且由用户选中的本地文件；不采集云端缓存 `~/.workbuddy/memory/`、聊天记录或配置。输出到项目 `CODEBUDDY.md`，保留已有内容并提示读取原 `AGENTS.md`。

WorkBuddy 的[官方记忆说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Memory)描述了账号内管理和导入；本地规则入口兼容性参考[Windows 桌面版加载器实测](https://github.com/yetone/magpie/issues/3142)。不同版本的本地格式可能不同，应在新会话中核对读取结果。

自定义 Agent 主目录及未列出的格式不自动识别。只读普通文件，跳过符号链接；单源最多 1500 个 Markdown / MDC 文件、最大 8 层，每文件最大 1 MiB。共享库上限 20000 个版本和解压后累计 64 MiB，超限或版本损坏会暂停输出并报告。

## 验证

`npm run desktop:check` 检查语法，`npm run desktop:test` 包含原有文件同步与 WebSocket 协议测试，以及 Agent Sync 的多设备隔离测试。Windows 受限环境下请将 `TEMP`、`TMP` 指向项目下独立测试目录；WebSocket 测试需要允许本机回环连接。

Electron `--smoke-test` 需同时指定全新的 `FFS_TEST_DATA`，会使用其中的假 Agent 主目录与假项目，检查原文件同步界面和 Agent 工作台，不读取用户真实记忆。测试覆盖项目表单、来源选择、提供入口、详情、历史和最小窗口无横向溢出，截图与 `smoke.json` 保存在该隔离目录。

自动化验证使用两个隔离的虚拟设备目录，没有替代 Windows / macOS 两台实体设备及四个真实 Agent 的用户试用。上线前按本节流程分别验证新会话读取和模型实际整理效果。
